# 说话人左键指认与多选批量指认优化计划

日期：2026 年 10 月 7 日。状态：方案稿，尚未实施。

目标是把原话中的人物指认变成一个看得见、点得快、范围明确的操作：左键点击头像里的“识”或说话人标签，直接弹出人物列表；需要连续处理时，勾选多条原话，再一次性指认给同一个人。

建议本轮一起交付左键快捷指认、多选批量指认和最近一次撤销。默认只修改当前句或明确勾选的句子；同声音组扩展作为单独、可预览的高级操作保留。

## 一 范围与现状

本次只编写计划，不实施代码、不修改真实录音归属、不重跑识别、不更新正式 App。后续开发按老板指定范围执行，正式安装仍沿用项目既有授权、备份和验证规程。

适用页面为工作台“原话”及“标记的原话”。主要入口是左侧圆形头像及说话人姓名区域。正文双击回听、右键修改文字、星标和“就这句问 AI”等既有操作继续可用。AI 分析卡片的归属确认沿用自己的流程。

本次源码核对基线为 `main` / `25e5ae6`，开始时工作树干净。依据是老板提供的截图和当前源码；未操作正式 App，未做本次功能的界面实测。

| 当前实现 | 对本次改动的影响 |
|---|---|
| `TranscriptPanelView` 通过右键菜单指认，头像和姓名未提供左键指认按钮 | 新增明确的左键入口和悬停提示 |
| 已有“指认或批量标注…”弹层，但批量指同组回填或其余未确认发言 | 仍需新增用户逐条勾选的批量模式 |
| 单锚点指认会按声音标签扩展，并可能登记声纹、启用后续标签映射和历史回查 | 快捷指认不能直接套用这条完整链路 |
| 人物未确定时，名称可能显示“识别中”；临时转写状态也使用“识别中” | 分开表达“人物未指认”和“文字尚未定稿” |
| 已有人工确认保护和保存失败处理 | 复用数据规则，补齐显式多选、完整字段回滚及专用撤销 |

## 二 单条指认

正常阅读时，点击头像或姓名区域即打开就近的小弹层。一次点击打开，一次点击人物完成；普通指认不再需要右键，也不再额外点“确定”。

| 用户操作 | 预期表现 |
|---|---|
| 鼠标移到头像或姓名 | 显示可点击样式及“指认说话人”提示，使用项目现有最小点击高度 |
| 左键点击“识”、未知人物标签或已有姓名 | 弹出人物选择面板，标题为“这句话是谁说的”，注明“仅修改这一条” |
| 点选本场已有说话人 | 保存后立即更新头像、姓名及颜色，关闭弹层，显示“已指认为人物甲 · 撤销” |
| 当前就是该人 | 以勾选状态展示；若尚未人工确认，则补人工确认；已确认且无冲突则不重复写入 |
| 人物较多 | 列表可滚动，并可按姓名或角色搜索；同名人物显示已有角色等可区分信息，使用稳定 ID 匹配 |
| 本场没有目标人物 | 提供“添加人物…”入口，复用已有本场人物创建或人物库关联能力，再返回指认流程 |
| 点击弹层外或按 Esc | 关闭面板，不改变数据 |
| 弹层打开后点击另一行头像 | 切换到该句，只保留一个人物选择面板 |

单条手工改判允许把“已人工确认给人物甲”的这一句改给人物乙；这是用户直接点选的结果。清除归属可保留在“更多操作”中，并具备同等撤销能力。

只把头像和姓名做成按钮，不把整段正文变成人物选择入口。按钮事件应与行级双击回听隔离，避免点两次头像时播放音频。键盘可聚焦按钮，Enter 或 Space 打开，Esc 关闭。

## 三 多选后批量指认

提供两个入口：原话页顶部的“批量指认”，以及单条弹层中的“选择多条后指认…”。从第二个入口进入时，自动勾选当前句。

1. 进入批量模式后，每条可操作原话左侧出现复选框；选中的行使用淡色底纹，并显示已选数量。
2. 左键点击复选框或头像区域可连续勾选、取消勾选，不反复弹出人物面板。正文继续承担阅读和回听。
3. 底部显示操作栏：`已选 6 条  ·  选择人物  ·  清空选择  ·  完成`。未选语句时，指认按钮不可用。
4. 点击“选择人物”，选定人物后预览实际范围，再点“将 6 条指认为人物甲”一次提交。批量流程保留这一步范围确认。
5. 保存成功后显示实际修改数及“撤销”，清空本批选择，保留批量模式，方便继续处理下一批；点击“完成”退出。

范围预览至少显示目标人物、选中数、可修改数、受保护数，以及按时间排列的语句摘要；合并录音增加来源名称和来源内时间。所有被排除的条目可查看原因，不只给一个总数。

批量模式的规则：

- 支持不连续的多条点选；本轮同时支持 Shift 选择当前展示顺序中的连续范围，不要求用户必须掌握快捷键。
- “全选当前列表”只选择当前人物筛选或标记页结果内的可操作语句，包含滚动区域外的匹配行，并明确显示总数；不等于全录音未确认发言。
- 改变人物筛选、切换原话与标记页或切换项目时，关闭选择弹层并清空选择，提示“列表范围已变化，已清空选择”。不保留不可见的勾选项。
- 关闭人物面板保留已选集合；再按 Esc 或点击“完成”退出批量模式。这里只清除未提交的选择，不需要额外确认。
- 多选时暂停自动追随新转写滚动；新到达的原话不自动入选。退出后由用户通过“回到最新”恢复跟随。
- 选中以片段 UUID 为准，不能用行号、时间戳或数组下标。分段变化导致已选片段失效时提示并重新预览，不把选择转移到邻句。

## 四 明确修改范围及保护规则

| 指认方式 | 修改范围 | 联动规则 |
|---|---|---|
| 单条快捷指认 | 点击的这一条 | 不自动扩展同组，不因本次操作学习声纹或启动整场回查 |
| 多选批量指认 | 明确勾选且通过校验的语句 | 不修改未选句，不把来自不同声音组的选择合并为一个声音组 |
| 同声音组指认 | 高级入口预览出的当前来源录音内同组语句 | 显示具体数量和受保护项；组级映射、声纹学习或历史回查的实际影响必须另行说明 |

左键单条和多选路径只调整人物归属，不能悄悄改变后续识别规则。已存在的独立自动识别任务按原规则继续运行，但不得把新的“仅这一条／仅所选”操作当成新增整组映射或自动学习授权。

同组及“本录音其余未确认发言”能力集中在高级入口；旧右键快捷人物项也要接入同一套明确范围规则，不能出现左键只改一句、右键同名动作却静默改一组。高级入口必须展示实际可修改数，不能拿声音标签总数代替修改数。

批量默认保护已经人工确认给其他人的语句：预览列出并跳过，不静默覆盖。例如选了 6 条，其中 2 条已确认属于人物乙，则对人物甲显示“将 4 条指认为人物甲，另 2 条保留原归属”。需要改判的两句通过单条入口处理。若全部受保护或无需变更，明确说明，不执行空提交。

人工确认后设置 `speakerWasUserConfirmed`，清除该句的 `speakerAttributionConflict`；保留文字、原始声音标签、时间、来源、星标及文字编辑状态。指认人物不能把文字标为 `.edited`，也不能锁死后续文字修订。

状态展示统一为：

- 人物未确认：显示“未指认”或已有“待识别 A”等分组名；头像“识”可保留，提示“点击指认”。
- 文字仍是临时转写：继续显示转写状态，点击可说明“本句定稿后可指认”，禁止提交，且不承诺固定等待秒数。
- 已有权威片段和有效文字、但识别任务失败：按片段是否稳定判断可否指认，失败提示仍然保留，不能把人工指认当成重试成功。
- 自动人物归属冲突：显示“归属待确认”，允许人工核对后指认。

## 五 保存与撤销

一次批量操作作为一个可恢复的变更单元：预校验、生成变更集、保存、刷新、反馈。保存期间禁止重复提交；保存失败保留原归属、弹层及已选集合，给出重试入口，不能先显示成功。

提交前重新校验片段存在性、稳定状态、来源资产、时间边界、目标人物和当前归属。预览后如果片段被重新切分、目标人物被删除或发生归属冲突，本次不使用过期预览提交，应更新范围让用户重新确认。原 UUID 仍存在也不代表还是原来那句话，重切后保留 UUID 的情况同样需要检查。

提供“撤销最近一次指认”，覆盖单条和批量操作。成功提示中提供入口，同时在原话页操作区保留可用的撤销按钮；提示消失后仍能撤销。首期仅在当前项目工作台会话内保留最近一次操作，离页或重启后不承诺恢复撤销记录。

撤销只恢复本次改动的归属字段、人工确认标记、归属冲突标记及新增的指认范围信息；不覆盖后来编辑的文字、星标、笔记或新转写，也不复活已删除片段或人物。若某条归属后来再次变化，或来源／时间边界表明该句已经重新分段，跳过该条并列明原因。普通文字修订不阻止归属撤销，修订后的文字保留。撤销本身保存失败时，保持撤销前状态及可重试记录。

涉及 `updatedAt` 的失败回滚和撤销分别处理：失败回滚恢复未成功提交的旧值；成功撤销作为新编辑记录当前时间，不能把后来其他编辑的时间回退。

指认成功及撤销成功均通知受影响片段的分析上下文刷新。已保存的旧总结和 AI 分析不直接改写成新结论；沿用现有过期检测或待更新提示，由既有流程或用户明确操作生成新结果。

| `Core/Diarization/SpeakerBackfill.swift` | 支持显式选段范围与保护规则，输出实际变更、跳过及原因；预览计算不得直接修改真实模型 |
| `Models/TranscriptSegment.swift` 及相关桥接／复制入口 | 必要时新增可选的指认范围或来源字段；同步更新转写 Reconciler、复制、合并及异步快照，保留旧 JSON 可解码，不依赖姓名作主键 |
| `Features/LiveMeeting/DiarizationController.swift` 及人工确认消费点 | 区分句级确认与组级映射，核对刷新、重开和后续分片的传播行为 |
| `Core/Diarization/HistoricalSpeakerRelabeler.swift`、工作台及 `Features/ProjectImport/ImportProcessingController.swift` | 组级推断只使用允许传播的确认；快照及迟到结果校验携带作用域，避免指认或撤销期间的旧任务回填 |
| 现有持久化、分析刷新及测试入口 | 使用 Project 真源和字段级保存，补齐失败回滚、撤销及范围验证；不整对象覆盖其他工作流数据 |

必须先处理的技术约束：

1. **不能循环调用旧单锚点指认。** 旧 `performTranscriptSpeakerAssign` 会同组回填，并可能抽样、登记声纹、更新前向映射和启动历史回查。对所选 N 条应生成一次变更集，完成一次逻辑提交和一次刷新通知。
2. **“本次不调用映射”仍不够。** `DiarizationController.rebuildSpeakerMapper` 会从 `speakerWasUserConfirmed` 的片段重建标签映射。需要持久地区分句级与组级确认；否则刷新或重开后，单条确认仍会变成整组规则。建议用可选作用域字段或独立组映射记录，开发时选择与当前模型最兼容的方案。旧记录缺字段时保留既有兼容语义，新记录明确写入范围。
3. **整场回查也要区分作用域。** 已核实 `HistoricalSpeakerRelabelMatcher.resolvedSpeakerIDs` 会把人工确认作为组级推断锚点。需让 `SegmentSnapshot` 携带作用域，推断时只使用允许传播的确认；工作台和导入处理两处快照构造、应用及迟到结果校验同步更新。指认范围变化或撤销应使旧推断失效，句级标注继续受人工保护。`HistoricalPersonLibrary` 的确认数量和沟通画像证据仍可使用句级确认；其声音样本拼接目前由显式声音注册入口调用，本次不把它改成自动行为，后续用户主动注册时按该入口披露及筛选素材。
4. **失败恢复要包含全部归属字段。** 当前指认快照覆盖人物、确认标记和时间，而回填还会清除冲突标记。新变更集和失败注入测试必须覆盖冲突标记及新增范围字段，不能只恢复姓名。
5. **合并录音隔离来源。** 显式选段可覆盖用户选中的不同来源，但组级扩展必须限定在同一来源录音内，不得仅凭相同的 `remoteSpeakerLabel` 跨录音传播；也不反写未授权的源项目。
6. **人物与归属事务保持一致。** 新建或关联人物复用既有 Person／Speaker 协调入口。人物创建成功但指认失败时说明两个结果，不伪报整体成功，也不遗留无主归属。
7. **重分段不能丢失作用域。** 当前 `TranscriptReconciler` 可能把旧 UUID 保留给第一条新片段。新增范围信息须随已有人工归属保护规则传递，不能因复制遗漏而退回旧记录的组级兼容语义；提交与撤销同时核对来源和时间边界。

## 七 实施顺序

| 阶段 | 交付内容 | 完成判定 |
|---|---|---|
| 1 范围与数据 | 显式 ID 集合、句级与组级区别、变更集、失败回滚、撤销 | 合成测试证明只改指定语句，刷新和重开不会扩大作用域 |
| 2 左键指认 | 头像及姓名弹层、人物点选、成功与撤销反馈 | 原生界面两次点击完成一条指认，且不误触回听 |
| 3 多选操作 | 批量入口、连续及不连续选择、预览、保护规则、批量提交 | 原生界面可完成多批处理，数量与实际修改一致 |
| 4 集成验收 | 录音中追加、失败及并发场景、旧入口一致性、产品文档更新 | 相关测试和真实界面流程通过，交付范围及未验事项写明 |

这四步属于同一优化任务；不以“左键能弹出”代替批量操作和数据范围完成。先实施数据范围是为了让快捷 UI 从一开始就具备明确语义。

## 八 验收标准

使用合成语句、合成人物和隔离数据目录，不把截图中的私有原文、人物或真实声纹写进测试及仓库。

| 场景 | 必须达到的结果 |
|---|---|
| 未指认与已识别人名 | 均可左键打开；点人物后只改当前句；取消不保存 |
| 不连续多选、Shift 范围和当前列表全选 | 数量准确，重复点击可取消，筛选变更后没有隐藏选择 |
| 同标签但未选中的句子 | 保持不变；新路径不自动注册标签映射或启动声音样本学习 |
| 刷新、退出重开、后续同标签分片到达 | “仅这一条／仅所选”的作用域仍然成立；自动任务不覆盖人工确认 |
| 句级指认后独立运行整场识别，或指认／撤销时旧任务返回 | 不把句级确认作为同组未选句的身份锚点；作用域变化使过期推断失效 |
| 已人工确认属于他人 | 批量预览明确排除；单条入口可显式改判 |
| 多来源录音碰巧标签相同 | 显式选段只改所选；同组扩展不跨来源 |
| 临时片段、失效 ID、人物删除、正在重新切分 | 禁止过期提交并说明原因；新到达语句不自动入选 |
| 云端重切后保留原 UUID | 句级作用域不丢失；旧预览及撤销不会误作用于时间／来源已变化的新片段 |
| 保存失败与连续双击提交 | 无部分成功假象，无重复副作用；冲突标记等字段完整恢复，选择可重试 |
| 指认后撤销、后续改稿或再次改判 | 恢复本次可撤销字段，保留后续编辑；冲突条目跳过并说明 |
| 缺少音频、没有声纹或识别服务不可用 | 已有稳定文稿仍可人工指认；快捷操作不依赖新的音频或云端请求 |
| 正文回听、右键编辑、星标及 AI 入口 | 手势不冲突，既有流程继续可用；键盘能够打开和关闭人物弹层 |
