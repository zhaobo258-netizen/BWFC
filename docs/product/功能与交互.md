# 功能与交互

> 当前源码基线：`dbce988`；核对日期：2026-10-07。本轮已完成录音收尾的隔离回归、使用生产 View 的合成原生 UI 验证及正式 App 更新后的版本、路径和历史列表核对。真实麦克风长录音、云端质量和历史资料重处理不在本轮验证范围；各层证据见[现状差异与验收](现状差异与验收.md)和[交付说明](../../交付说明.md)。

## 1. 从哪里开始

应用默认进入“开始录音 / 导入音视频 / 最近项目”首页；首页另有“人物库”“业务项目”和设置入口。设置是 Root 级弹层。当前窗口最小尺寸为 960 × 640，默认尺寸为 1440 × 900。

当前“项目”通常指一场录音、一次导入或一份跨录音派生分析；长期业务事项使用独立的 `BusinessProject`。首页分类与真正的业务项目必须区分：

| 界面与概念 | 当前作用 | 不应推导的含义 |
|---|---|---|
| 首页“归入业务项目” | 修改录音 `Project.businessCategory` 分类文字，支持搜索已有分类、建立新分类、移出分类 | 不会直接创建 `BusinessProject` 或写入其录音关联 |
| 首页“业务项目”入口 | 打开独立业务项目页，管理稳定 ID、目标、背景、人物、关联录音和跟进 | 不是分类字符串的另一种显示方式 |
| 业务项目页“从业务分类归组建议” | 用户明确选择后，建立业务项目并关联建议中的录音 | 同名分类不会自动成为同一个业务项目 |

旧 `MeetingList / MeetingSetup / LiveMeeting / MeetingReview` 页面和路由仍保留兼容。它们不再是首页主流程；启动恢复中打开未迁移的旧会议仍可能进入旧回看页。旧会前表单、我方/对方阵营和旧 Markdown/JSON 导出不可直接写成当前录音工作台的功能。

源码：[AppRouter](../../App/AppRouter.swift)、[RootView](../../App/BangWoFenXiApp.swift)、[首页](../../Features/ProjectHome/ProjectHomeView.swift)、[业务项目页](../../Features/BusinessProjects/BusinessProjectPage.swift)。

## 2. 首页：录音、导入与整理

### 2.1 开始录音

1. 不要求预填标题、背景、人物或声纹。首次点击录音显示参与者知情确认；确认状态在本机保存，后续直接创建项目并进入工作台开录。
2. 录音场景默认“自动判断”，选项默认收起。可预选客户拜访、内部会议、访谈采访、课堂培训、自由记录；每次回到首页重新回到自动判断。该预选只作用于现场录音，工作台仍可调整场景。
3. 默认标题为“未命名录音 · HH:mm”。已有自动带入的声音档案可转成本场人物引用；声音档案读取失败时带警告继续创建，不以此阻止录音。
4. 麦克风权限缺失时说明原因并打开系统授权入口，项目保留“开始录音”重试入口。原持久存储不可用时禁止新建录音，避免另起分叉资料库。
5. 本地转写资源不可用或启动失败时，当前代码会自动进入“仅保存音频模式”并提示，结束后可重新转写。这不是“用户已选择云端替代”，也不能显示为已经获得文稿。

源码：[ProjectHomeView.startRecordingProject](../../Features/ProjectHome/ProjectHomeView.swift)、[ProjectHomeSupport.makeRecordingProject](../../Features/ProjectHome/ProjectHomeSupport.swift)、[ProjectWorkspaceView.beginRecordingSession](../../Features/ProjectWorkspace/ProjectWorkspaceView.swift)。

### 2.2 导入音视频

- 文件选择器接受系统识别的音频/影片类型；拖放落点是“导入音视频”卡片。界面列举 m4a / mp3 / wav / mp4，实际可解码能力由 UTType 与 AVFoundation 决定，不是四种扩展名白名单。
- 一次选择一个文件，拖入多项只取第一个符合条件的候选；同时只运行一个导入/重新转写流水线。
- 检查文件可读、有可解析音轨、时长大于零，通过后创建项目并进入工作台。目录、无音轨、零时长、损坏或系统不支持的文件有明确错误。当前未实现重复导入内容去重，不应承诺重复文件会被阻止。
- 保留外部原件不变；先复制原件到本项目目录，再提取统一音轨供处理。导入标题默认使用文件名去扩展名，来源由实际音视频轨判断。
- 流水线按“提取音轨 → 本地转写 → 分人 → 分析 → 完整总结”执行，后三项按实际配置建立任务。任一阶段失败阻断后续，已完成阶段保留；“暂停处理”保留可续跑状态，“继续处理”从未完成阶段恢复。
- 必需的提取/转写失败与可选分析失败分别呈现：可恢复的必需阶段未完成仍为处理中；必需阶段不可恢复失败为失败；必需阶段已完成、可选阶段有缺口为就绪但有告警。不能把“有项目记录”当成“处理成功”。

源码：[导入服务](../../Core/Import/AudioImportService.swift)、[ImportPlanner](../../Core/Import/ImportPlanner.swift)、[ImportProcessingController](../../Features/ProjectImport/ImportProcessingController.swift)。`knowledgeExpansion / obsidianArchive` 虽存在于任务枚举，当前导入计划不创建这两类任务，不可据此宣布自动知识扩展或自动归档已接通。

### 2.3 查找、分类和跨录音合并

首页按分类分组，组与组内录音按最近活动排列，未分组录音放在后面。支持打开、重命名、分类、移出分类、Finder 定位和删除。当前首页没有全库标题搜索或逐字稿全文搜索入口；分类选择弹层的搜索只检索分类名，AI 按问题取证也不是项目列表搜索。

“跨录音合并”创建新的派生分析项目，保留每条原话对应的来源录音，不修改原录音。条件为至少两段原始录音、状态为就绪或有告警且含非空最终/人工修订文稿；已经合并的项目不能再次作为原始录音参与。所选录音必须属于同一个分类，或全部未分组，不能把未分组与已分类录音混合。配置分析服务时会启动完整总结，否则仍可查看合并文稿。合并依据的是首页分类文字，不是业务项目 ID。

源码：[ProjectHomeSupport.groupedForDisplay / makeCombinedAnalysisProject](../../Features/ProjectHome/ProjectHomeSupport.swift)、[ProjectHomeView.createCombinedAnalysis](../../Features/ProjectHome/ProjectHomeView.swift)。

## 3. 工作台：理解与回看、笔记与 AI

当前内容区是 A 版双区布局，不再是旧“左文稿 / 中分析 / 右笔记”固定三栏。左区为“理解与回看”，右区为“笔记与 AI”。正文可用宽度不足 800 时切换为单区，通过分段控件选择两个区；宽窗口可显示项目侧栏，较窄窗口用浮层打开项目列表。窗口宽度与正文可用宽度是两个不同断点，不能承诺所有 960 宽窗口都只显示单区。

| 位置 | 入口与动作 | 当前边界 |
|---|---|---|
| 顶部 | 返回项目、修改标题、录音状态、关联上下文、人物库、说话人、导出、处理详情 | 录音中返回需选择结束并返回；保存失败阻止相关导航，保留重试机会 |
| 理解与回看 → 整体理解 | 实时总结、完整总结、动机与目的、开花 | 四个页签不是四份同等权威的原文；推断及外部资料保留来源性质 |
| 理解与回看 → 人物 | 按人物整理明确发言、诉求、可能动机与待确认 | 明确表达与 AI 推断分层，人物归属仍可人工确认 |
| 理解与回看 → 原话 | 按人筛选、修改文字、指认人物、星标、就这句问 AI、回听 | 没有文稿时给出回听收音与重新转写建议，不伪装为空白的完成态 |
| 理解与回看 → 标记 | 查看已星标原话 | 空态引导在原话行星标；不是独立录音或知识库 |
| 笔记与 AI | 手写笔记、AI 对话、AI 归结 | 手写正文和每轮 AI 归结独立保存 |

顶部“关联上下文”明确选择其他录音，供后续请求引用历史背景；关联背景不能当成本场原话。工作台“人物库”按钮当前打开声音档案/历史人物管理弹层，首页“人物库”才是独立 `PersonLibraryPage`；两个入口不能在操作说明中混为同一页面。

源码：[ProjectWorkspaceView](../../Features/ProjectWorkspace/ProjectWorkspaceView.swift)、[WorkspaceZoneLayout](../../Features/ProjectWorkspace/WorkspaceZoneLayout.swift)、[RelatedProjectContextSheet](../../Features/ProjectWorkspace/RelatedProjectContextSheet.swift)、[PersonUnderstandingView](../../Features/ProjectWorkspace/PersonUnderstandingView.swift)。

### 3.1 录音与回听

录音条提供输入电平、低音量提醒、标记、暂停/继续、结束。麦克风断开有更换设备与恢复入口；写入失败必须可见。“结束录音并返回”先停止采集、关闭音频文件并保存状态，成功后返回首页；保存失败保留当前界面供重试。尾部转写和分人继续整理，各自默认最多等待 8 秒；超时保留原音频、已有文稿及待重试分片，未完成转写不会自动生成总结。新工作台使用独立转写会话，旧收尾不能停止新录音。

界面区分“录音已停止，正在整理…可返回首页”和总结完成。整场说话人识别默认最多等待 20 分钟，停止识别或离页时不再等待其底层请求完成，迟到结果不能写回。文稿复查、整场识别及总结等 AI 收尾仍由工作台任务串联，尚不保证整条链在退出 App、重启后自动续跑。合成原生 UI 已验证结束返回、立即开启下一场、正常结束和退出；真实麦克风与长录音仍需独立验收。

符合续录条件的现场录音有“继续录制”，追加到原项目，不覆盖原录音和文稿；导入或派生项目不能按现场续录处理。正在重新处理或识别说话人时，不能同时启动同一项目续录。

停止录音后的原话页提供播放/暂停、进度拖动、“识别说话人”和“重新转写”。双击原话可从对应位置回听；点击证据先打开来源抽屉，再由用户选择回听；合并分析按来源录音及暂停时间换算播放位置。音频丢失时明确说明，已存文稿仍可查看。合并分析不提供对派生项目整体重新转写/整场分人入口。

源码：[ProjectWorkspaceView.playbackBar / preparePlayback / beginRecordingSession / finishRecording](../../Features/ProjectWorkspace/ProjectWorkspaceView.swift)、[Project 续录策略](../../Models/Project.swift)。

### 3.2 手写笔记与 AI 归结

- 手写笔记使用原生稳定编辑器；Return 换行，不触发模型。停止输入后默认 800 毫秒防抖保存，离页等时机立即保存；这是实现参数，不是任何磁盘故障下都保证 1 秒落盘的承诺。
- 笔记区默认约占右区高度的 25%、上限 180；窗口高度不足时收起，仍可进入“专注手写笔记”窗口编辑。保存失败保留正文、显示错误并提供重试。
- “供 AI 使用”是项目授权开关，默认关闭；新项目对话和开花读取编辑器当前笔记；完整总结读取已保存笔记；旧轮重试遵循其快照。授权不等于逐键上传，也不让外部知识源读取整篇笔记。
- AI 每轮归结独立保留，用户可以主动“摘入笔记”；按稳定 ID 去重、仅追加，不覆盖已有手写内容。清空聊天不删除手写笔记、已归结笔记与逐字稿。
- 当前授权笔记可以进入完整总结的“我的思考与 AI 共创”部分，不能混入录音事实。设置隐私说明中的“完整总结仍不读取笔记”是遗留文案，不是当前数据规则。

源码：[ThoughtWorkspaceView](../../Features/ProjectWorkspace/ThoughtWorkspaceView.swift)、[NoteController](../../Features/ProjectWorkspace/NoteController.swift)、[ProjectAIChatView](../../Features/ProjectWorkspace/ProjectAIChatView.swift)、[完整总结服务](../../Core/Analysis/FinalReportService.swift)。

### 3.3 AI 对话与证据

当前 A 版输入区 Return 换行、Command Return 发送。可附加 PDF、Word、Markdown 或文本作为参考材料，选择联网及 Obsidian 检索，并展开完整轮次阅读。默认联网搜索开启，Obsidian 检索关闭；实际发送受本轮范围和来源配置约束。

“整场原文”范围仍受上下文容量与相关片段选择限制，每轮披露实际覆盖；未找到某项证据不等于整场没有。点击原话“就这句问 AI”进入严格片段范围：新轮次仅使用所选有效片段，不混入整场历史、笔记、引用文档、联网或 Obsidian 来源。

AI 回答保存发送时的原话、上下文快照与本轮实际来源。失败重试冻结原话、上下文及已准备的 Obsidian 资料，但可能重新搜索公开网页。当前原话修改后，历史来源与当前内容分开展示；可回到当前原话、回听、就当前内容追问，或回到对应对话轮次。轮次已清空或超出保留范围时提示不可定位，不能跳到另一轮冒充原来源。请求失败有原位重试，不重复追加用户消息。

只有明确纠错意图且原话匹配有效时才能修改文稿；普通提问、否定修改与背景补充不能视为授权。模型建议、人工背景和外部知识始终不具有本场逐字稿的证据地位。

源码：[ProjectAIChatView](../../Features/ProjectWorkspace/ProjectAIChatView.swift)、[ProjectAIChatController](../../Features/ProjectWorkspace/ProjectAIChatController.swift)、[ProjectAIChatService](../../Core/Analysis/ProjectAIChatService.swift)、[EvidenceRoute](../../Features/ProjectWorkspace/EvidenceRoute.swift)。

### 3.4 总结、开花与候选

实时总结随有效片段增量更新；完整总结是独立版本，通读最终/人工修订文稿，展示生成中、失败、可重试及过期状态。结束录音或导入处理后可生成，AI 共创更新也可能触发后续完整总结更新。完成提示可跳转报告，约 8 秒自动收起，报告页签仍保留入口。

开花从有原话依据的知识种子出发，主动发起、停止或重新生成，补充 Obsidian、互联网和已验证的只读 MCP 来源。当前工作台以 `automaticallyBloomNewSeeds: false` 建立控制器；打开历史项目不自动对新种子发起外部检索。没有有效证据或来源失败时如实展示，不能把空检索当成已得到外部证明。

“记忆候选”在存在有效最终文稿且处于可用状态时出现；无候选可手动提取，有候选则打开确认。记忆与跟进在确认前不生效，业务作用域需明确选择；保存结果已写入但候选状态未成功回写时有“恢复候选状态”，该恢复不调用模型。

源码：[FinalReportView](../../Features/ProjectWorkspace/FinalReportView.swift)、[FinalReportCoordinator](../../Features/ProjectWorkspace/FinalReportCoordinator.swift)、[KnowledgeGardenView](../../Features/ProjectWorkspace/KnowledgeGardenView.swift)、[KnowledgeGardenController](../../Features/ProjectWorkspace/KnowledgeGardenController.swift)、[MemoryCandidatesSheet](../../Features/ProjectWorkspace/MemoryCandidatesSheet.swift)、[工作台控制器接线](../../Features/ProjectWorkspace/ProjectWorkspaceView.swift)。

## 4. 人物与业务项目

### 4.1 独立人物库

首页人物库支持无声音样本创建人物、编辑姓名/角色/人工背景、设为“我”、关联或解除本场说话人、合并、删除及撤销最近一次人物操作。稳定 `Person.id` 承担跨录音身份，名字只是显示字段，声音档案是可选附件。

人物页可查看关联录音、有效背景、记忆及其来源，支持忘记、重新确认或另存人工背景等显式处理。“声音档案管理”进入独立声音管理页面，处理样本、自动带入和 Provider 注册；不能因为人物存在就宣称已登记声纹或自动认人可靠。工作台指认按当前录音的可信声音组传播，已人工确认属于他人的片段不得被批量覆盖。

源码：[PersonLibraryPage](../../Features/People/PersonLibraryView.swift)、[HistoricalPeopleLibraryView](../../Features/Settings/HistoricalPeopleLibraryView.swift)、[SpeakerAssignSheet](../../Features/ProjectWorkspace/SpeakerAssignSheet.swift)、[SpeakerPanelView](../../Features/ProjectWorkspace/SpeakerPanelView.swift)。

### 4.2 业务项目与跟进

独立业务项目页支持创建项目、填写目标与有效背景、选择参与人物、关联录音、归档/恢复，并查看跟进数量和逾期提示。空态说明从录音候选确认形成跟进；当前不应写成完整销售管理、外部 CRM 同步或自动任务执行系统。

跟进按“待跟进 → 进行中 → 已完成”管理，进行中可恢复待跟进。完成必须填写非空实际结果；点击完成不意味着客户接受。可从跟进返回来源录音及证据；责任人与期限不能因 UI 需要而由系统臆造。

源码：[BusinessProjectPage / BusinessProjectDetailPane](../../Features/BusinessProjects/BusinessProjectPage.swift)、[BusinessProject](../../Models/BusinessProject.swift)。

## 5. 设置与配置生效

| 分类 | 当前入口与能力 | 生效及限制 |
|---|---|---|
| 大模型与 AI | Kimi 账号/备用 Key、模型选择、一个 OpenAI-compatible 文本连接、连接测试、提示词版本 | 下一次请求生效，不改投在途请求；普通设置不编辑原始 Prompt |

| 词库与纠错 | 词条检索、添加、编辑、导入、清空；纠错规则管理 | 专业词条从下次录音/导入生效；纠错规则可作用于当前录音后续最终片段，不自动改历史稿 |
| 人物库与我的背景 | 当前嵌入历史人物/声音档案管理 | 与首页独立人物库的主档入口区分 |
| 录音与说话人 | Provider 选择、各服务独立配置与测试、本地模型检测 | 当前包括关闭、OpenAI 兼容、火山、讯飞、本地分人实验；队列冻结原 Provider，不静默迁移 |
| 存储与隐私 | 查看当前目录、选择或恢复原 Obsidian Vault、Finder 定位、隐私说明 | 录音/导入/收尾时禁止切换；正常切换先复制校验并保留旧目录；原库不可用时仅恢复原库授权 |

当前 Kimi 默认 `k3-256k`，可选 `k3`、`kimi-for-coding`；服务权限不足时不静默改用其他模型。本地分人需要本机模型与引擎，只做整场识别，不参与会中分片，超过 2 小时不做整场识别。设置可见与测试连接成功，都不等于真实录音的转写或声纹准确率已经验收。

凭据按当前明确选择明文存于本机配置，各 Provider 和 MCP 分开；界面不回显原值，不写入项目、日志、导出或 Git。不能沿用旧文档的 Keychain 存储描述。

## 6. 失败恢复、导出与删除

| 状态或操作 | 当前用户反馈与恢复路径 |
|---|---|
| 启动发现未正常结束 | 恢复弹层可查看、标记结束或稍后处理；查看本身不改变处理状态，保留已落盘音频与文稿 |
| 首页残留录音 | 非阻塞提示，可查看首个或全部标记结束；已知失败任务不应冒充崩溃 |
| 云端分片/分析失败 | 工作台处理详情与暂停提示区分配置、执行结果、队列问题，并给出重试入口；收尾超时保留 pending 分片，队列写入失败及未完成分片记录为可重试状态 |
| 导入中断 | 各阶段状态保留，暂停后可续跑；原件副本未形成等不可恢复条件必须明确报错 |
| 笔记或其他写入失败 | 保留当前编辑与可恢复状态，显示失败，不能仅靠内存已更新宣称保存完成 |
| 原音频缺失 | 文稿仍可读，回听明确失败，不定位到其他录音替代 |
| 总结失败或原文变化 | 保留旧版，显示重试/需更新，不把旧版冒充最新 |

当前导出由工作台“导出”打开资料选择弹层，默认勾选所有实际可用内容。可选原始录音、完整转写、实时总结、动机与目的、完整总结、开花与知识延展、AI 共创记录、项目笔记；无内容的项禁用。用户选择父目录后创建独立资料文件夹，其中是音频副本和分项 Markdown，成功后在 Finder 显示。导出先写临时目录，再整体移到目标目录；失败显示错误。录音、暂停和收尾时导出入口禁用。

V2 工作台当前没有 JSON 往返导入/导出入口。合并分析没有一份新的原始音频，不能承诺导出包包含所有来源音频；其证据回听仍依赖关联原录音。导出文件不是完整数据库备份，也不是 Obsidian 自动同步。

删除由首页执行，先核查活跃录音/导入，再二次确认列明音频、样本、临时分片、队列、文稿、分析、总结、笔记和共创内容。删除导入项目包含应用保存的原件副本，外部原文件不受影响；删除派生合并分析不删除来源录音。应用外已经导出的文件不会随项目删除。人物删除、录音删除和业务项目归档是不同操作。

源码：[RootView.handleRecovery](../../App/BangWoFenXiApp.swift)、[ProjectHomeSupport](../../Features/ProjectHome/ProjectHomeSupport.swift)、[ProjectWorkspaceView.ProcessingDetailsButton](../../Features/ProjectWorkspace/ProjectWorkspaceView.swift)、[ProjectExportSheet](../../Features/ProjectWorkspace/ProjectExportSheet.swift)、[ProjectExportService](../../Core/Export/ProjectExportService.swift)。
